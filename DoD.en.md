# Definition of Done (DoD)

## General Principles

> Baseline quality (freedom from typos, readability, absence of bugs, logical structural consistency, security, and performance) is ensured through static analysis and AI-assisted support.
> The development team prioritizes **achieving the sprint goal (customer business objectives and problem resolution)**.

---

## High-Level Design (HLD)

- [ ] Development team has confirmed sprint goal achievement and problem resolution
- [ ] Complete set of deliverables is in place
- [ ] AI review completed; responses to findings or justifications for dismissal are recorded

## Program Code & Configuration Files

- [ ] Development team has confirmed sprint goal achievement and problem resolution
- [ ] All HLD requirements are implemented
- [ ] All planned files have been created or modified
- [ ] Changes are committed to the task branch
- [ ] Usage scenario testing based on user stories is complete; ready for integration testing
- [ ] No known critical bugs or security issues
- [ ] Any intentionally deferred technical debt has a corresponding ticket
- [ ] PR is created and ready to merge (no conflicts)
- [ ] AI review completed; responses to findings or justifications for dismissal are recorded

## Integration Testing

- [ ] Development team has confirmed sprint goal achievement and problem resolution
- [ ] Test cases covering sprint goal verification are comprehensive
- [ ] Test cases exist for all HLD requirements
- [ ] All cases have been executed and pass/fail is recorded (waivers documented for failures)
- [ ] AI review completed; responses to findings or justifications for dismissal are recorded

## Low-Level Design (LLD)

- [ ] All deliverables defined in the prescribed artifact list (defined separately) are present
- [ ] AI review completed; responses to findings or justifications for dismissal are recorded

---

## Release Readiness

- [ ] Ready for PO acceptance review at sprint review
- [ ] Releasable at any time
